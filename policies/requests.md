# 削除・訂正・辞退の求め

最終更新：2026-11-15。

## 求めることができるもの

- 騎士の名簿からの辞退（名を外す）。
- 名簿や issue に書かれた、自分についての記載の訂正・削除。
- 自分についての保有個人データの利用目的の通知・開示・訂正・追加・削除・利用停止・消去・第三者への提供の停止。
- 自分の個人情報が、自分の同意なく書かれている場合の削除。
- 自分の名誉や信用を傷つける内容の削除。
- 自分の権利（著作権・商標・肖像など）を侵す内容の削除。
- ヌスクァマが実在の何かと誤認されるおそれがあるときの、表現の修正。

費用はかかりません。
求めは、住んでいる国や国籍を問わず、どの国の人からも同じ手順で受け、同じ速さで答えます。日本語でも英語でも受けます。

## 求め方

[削除・訂正・辞退の求め](https://github.com/cpsbvbng26-dotcom/nusquama/issues/new?template=request.yml)の様式で issue を開き、どの記載について、何を求めるかを書きます。
GitHub の画面で issue を開くときは、様式だけを選べるようにしてあります（白紙の issue は、リポジトリに書き込める人の画面にだけ出ます）。
GitHub の API など、ほかの道で開かれた issue は、運営者が読みます。ただし、叙任の願い出の受付を止めているあいだに開かれ、題か本文に叙任の願い出の様式の見出しや印を持つ issue は、叙任の願い出と同じに扱います（[叙任の規程](./knighting.md)「受付の停止」）。
窓口は GitHub だけです。ヌスクァマは、GitHub の外に連絡先を持ちません。GitHub の無料のアカウントで足ります。
求めは、代理人が出すこともできます。そのときは、本人の GitHub アカウントから、代理を頼んだことを issue に一言書いてもらいます。
問題の個人情報そのものを、issue に書き写さないでください。どこにあるかだけを書きます。

## 公開できない求め

ヌスクァマには、非公開で求めを受ける窓口がありません。
GitHub の非公開の脆弱性の報告（private vulnerability reporting）を、公開できない求めの非公開の窓口として開くと、2026-11-15 に利用者が決めました。この機能の本来の用途は安全の弱点の報告で、求めを受けるのは本来の用途の外の使い方です。
この窓口が使えるのは、このリポジトリでこの機能が有効になってからです。2026-11-15 に GitHub の API で確かめたとき、有効になっていませんでした。有効になるまでは、次の手順によります。
公開の場で書けない事情がある場合は、様式の種類で「非公開の連絡を求める」を選び、ほかは空のまま出します。issue に出るのは、GitHub のアカウント名と題と種類だけです。
運営者は、求めた人が自分の GitHub のプロフィールに連絡先を公開しているときだけ、その連絡先へ非公開で答えます。
そうした連絡先がない人も、連絡先を自分のプロフィールに一時的に公開すれば、その連絡先で答えを受け取れます。
連絡先を公開しないときは、個人の事柄を書かずに、issue で答えます。
サイトやリポジトリの安全の問題も、同じ手順で知らせます（[安全の問題の知らせ方](../SECURITY.md)）。

## 求めを受けた後

運営者は、それぞれの求めに 7 日以内に答えることを目指します。
個人情報の露出のように害が大きいものは、判断の前に、その記載をただちに外します。
他人の名誉や信用を傷つける記載も、判断の前に、ただちに外します。外したあとで、外したことが正しかったかを確かめます。
外したことが正しくなかったと分かったときは、元に戻し、書いた人に issue で知らせます。
ほかの人が書いた issue やコメントを、自分の権利を侵すとして外すよう求められたときで、上の二つ（個人情報の露出と、名誉や信用を傷つける記載）でないものは、運営者が求めの中身を読みます。他人の権利が不当に侵害されていると信じるに足りる相当の理由があると運営者が考えたときは、外します。
そう考えないときは、書いた人に、侵害されたとする情報と権利と理由を示し、外すことに同意するかを、その issue で尋ねます。尋ねた日から 7 日を経ても、同意しないという申出がなければ外します。申出があったときは、運営者が判断し、求めた人と書いた人に issue で知らせます。
どの場合も、外すのは、権利を侵すとされた記載だけです。
issue やコメントに書かれた連絡先の形の文字は、運営者のもののほかは、求めを待たずに、自動の確認がその文字だけを伏せます（[個人情報の取り扱い](./privacy.md)「安全のための措置」）。
名簿からの辞退は、理由を問わず応じます。
開示・訂正・利用停止などの求めには、遅滞なく応じます。開示は、求められた方法で行います。電磁的記録で求められたときは、電磁的記録で渡します。
求めに応じたときは、何をしたかを遅滞なく知らせます。求められたデータがないときや、求められた方法で渡せないときも、その旨を遅滞なく知らせます。
求めに応じない場合は、その理由を答えます。
2026-12-01 から、誤りの知らせは突き合わせの受付で確かめます。引いた語がなければ、ラベル「not verified」と決まった文のコメントを付けます。突き合わせの受付は、どの issue も閉じず、鍵も掛けず、運営者が読みます。
2026-12-01 から、誤りの知らせは、日本にいる人からだけ受けます（[誤りの知らせ](https://github.com/cpsbvbng26-dotcom/nusquama/issues/new?template=error.yml)の様式）。この求めの様式で出す求めは、どの国の人からも受け、この限りに掛かりません。
自分についての記載の訂正や削除、辞退、権利、個人の情報、同意を求めるときは、この求めの様式を使えます。誤りの知らせの様式に書いた求めも、閉じることはありません。法令が受けて扱うことを求める求めを、どの言語でどう書かれても、確かめずに退けないためです。

## 発信者情報の開示の求め

情報流通プラットフォーム対処法第5条第1項は、特定電気通信による情報の流通によって自己の権利を侵害されたとする者が、特定電気通信役務提供者に対し、その者が保有する発信者情報の開示を請求できると定めます。同項第1号は「当該開示の請求に係る侵害情報の流通によって当該開示の請求をする者の権利が侵害されたことが明らかであるとき。」を要件の一つに挙げます。
同法第6条第1項は、開示の請求を受けた提供者が「当該開示の請求に応じるかどうかについて当該発信者の意見（当該開示の請求に応じるべきでない旨の意見である場合には、その理由を含む。）を聴かなければならない。」と定めます。
ヌスクァマへの発信者情報の開示の求めは、この求めの様式で受け、次のとおりに扱います。

1. どの記載についての求めかと、侵害されたとする権利を確かめます。
2. 書いた人に、開示に応じるかどうかについての意見を issue で尋ねます。連絡できないときや特別の事情があるときは、そのことを記します。
3. 法令が求めるもののほかは開示しません。運営者が持つのは、GitHub のアカウント名と、issue に書かれたことだけです。それより詳しい発信者の情報は、issue を記録している GitHub が持ちます。
4. 求めに応じないときは、その理由を答えます。同法第8条により、裁判所に発信者情報開示命令を申し立てることもできます。

## 外せないもの

リポジトリの過去の版は、履歴を書き換えない限り残ります。ほかの者がすでに写したものは、運営者の手の外にあります。
Vercel に残る過去の配信は、求めがあれば、その記載を含むものを Vercel から消します。
リポジトリの履歴から消す必要がある場合は、運営者が GitHub にその削除を求めます。
2026-12-01 から、求めに応じて履歴から名簿の行を消す前に、その行の提供の記録の項目（足した日、受け手が不特定かつ多数の人であること、本人を指すアカウント名、載せた項目、同意を得たこと）だけを、`docs/records-of-provision.md` に別に記します。名簿のほかの中身は記しません。個人情報保護法第29条がこの記録を求め、同法施行規則第21条第3号が保存の期間を「三年」と定めるため、この項目は記した日から三年、そこに公開のまま残ります。
